## QA findings

- S0 is the critical quality gate. If S0 under-builds the report schema, anti-drift scan, or command topology, later scenarios can create fake completeness.
- Scenario implementations must not fabricate evidence reports without driving real public/runtime paths where the underlying primitive exists.
- Some scenario coverage may reveal underlying 0.1 primitive gaps; those must be fixed through scoped implementation PRs or escalated if they materially alter architecture/scope.
- The suite must distinguish deterministic fixture services beyond adapter boundaries from mocks that replace Splendor enforcement internals.
- S0 established a review precedent: placeholder reports, private-helper claims, optional container execution, and insecure daemon exposure are blocking defects even when local scripts appear green.
- S0 contract output intentionally marks missing fleet/messages/governance/physical API groups as `blocked_not_yet_covered`; later scenario agents must either implement executable public paths or keep those scenarios blocked rather than claiming pass.
- S1 established a review precedent: side-effect boundary negatives must be verifier/gateway denials before adapter execution, replay lifecycle evidence must come from raw public replay output with canonical trace IDs, and state-linkage evidence must name real state node parents.
- S2 established a review precedent: management API operation coverage through raw HTTP is not sufficient to claim full API/client acceptance; executable TypeScript client, Python SDK daemon-client, and CLI daemon-wrapper paths must either run the workflow or remain explicitly blocked/not-yet-covered.
- S2 final QA established a security precedent: replay/export POSTs are management mutations for audit purposes and must reject missing, null, or principal-mismatched caller/audit authority even though replay remains inspect-only and side-effect suppressed.
- S3 established a review precedent: local public Rust primitives are acceptable scenario boundaries only when reports prove real trace/state/replay artifacts; synthetic trace IDs, unrelated denial events, or state hashes that do not match `state.committed` trace payloads are blocking defects.
- S3 schema review established that canonical optional-like fields required by the acceptance contract must be treated consistently across Rust/Python/TypeScript/docs; `Message.causal_parent` is now required-but-nullable and omission is rejected.
