# Splendor 0.04-dev Release Notes

## Status

0.04-dev is the governance-workflows release. It builds on the 0.01 local
kernel baseline, the 0.02 local multi-agent and daemon-control surface, and the
0.03 resident/fleet foundation. The release adds first-class governance state,
approval gating, deterministic escalation, circuit breakers, policy bundle
TTL/revocation enforcement, external governance adapter contracts, and
inspect-only governance replay/audit export.

The release remains a development milestone, not the 0.1 stable compatibility
line.

## Implemented primitives

- Governance state schemas for approvals, escalations, interventions,
  circuit breakers, and kill switches with typed IDs, explicit scopes, issuers,
  expiry/revocation fields, transition validation, and trace linkage.
- Approval verifier support in the Action Gateway so approval-required actions
  return `needs_approval`, pause daemon runs, and resume only after scoped
  approval evidence re-enters the verifier/gateway path.
- Deterministic escalation policy evaluation for verifier uncertainty,
  repeated denial/failure, approval timeout, quota pressure, policy expiry, and
  safety-risk observations.
- Circuit-breaker enforcement for global, fleet, node, instance, tenant, agent,
  adapter, action, and action-class scopes. Tripped breakers deny before adapter
  execution and are visible in trace/replay.
- Signed policy bundle distribution primitives with local cache, TTL checks,
  revocation handling, degraded cached-policy mode, and policy metadata in run
  and trace context.
- Provider-neutral external governance adapter contracts, including
  Harmony-compatible endpoint maps, scoped work-order bridge shape validation,
  external approval grant/denial mapping, fail-closed adapter failure mapping,
  and trace-linked governed artifact references.
- Governance replay and audit export. Replay and `splendorctl audit export` open
  trace/state stores read-only, recompute trace hash chains, validate referenced
  state evidence, redact credential-shaped data, and never replay side effects.
- Docker deployment image packaging for the 0.04-dev local governed runtime
  surface with `splendorctl`, `splendor-daemon`, the Python SDK, local examples,
  and `linux/amd64` plus `linux/arm64` manifests.

## Compatibility notes

- Rust, Python, and TypeScript package versions currently report `0.1.0`; the
  milestone release label is `Splendor0.04-dev`.
- Public schemas remain development-stage and provisional until the 0.1 stable
  primitive spec.
- TypeScript packages do not execute policies, verifiers, gateways, adapters,
  state commits, trace writes, or replay. Runtime enforcement remains in Rust.
- External governance adapter contracts are boundary contracts only. External
  systems may issue scoped work orders and approval objects, but they do not own
  Splendor runtime enforcement and cannot bypass the Action Gateway.
- The Docker image is a deployment/install artifact for local governed runtime
  smoke tests. The included daemon remains explicit local-only insecure
  development mode and must not be exposed as an unauthenticated remote service.
- Release image manifests are published for `linux/amd64` and `linux/arm64`;
  other architectures are not part of this release line.

## Explicitly not included

- No approval UI, enterprise IAM integration, broad workflow language, ticketing
  integration, notification platform, approval queue product, monitoring
  platform, dashboard, enterprise policy authoring product, global policy
  consensus, production PKI/key management, or compliance certification claim.
- No product-specific Harmony dependency inside kernel enforcement. Harmony is
  supported only through provider-neutral external governance adapter contracts.
- No kill-switch propagation from a central manager to resident instances beyond
  the 0.04 governance state and trace model.
- No physical/edge device orchestration, robotics adapter contract, safety
  verifier API, hard real-time robot control, or production robotics safety
  certification.
- No stable 0.1 compatibility guarantee yet.
