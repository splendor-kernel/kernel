## Global Guardrails

Every sprint in this file must preserve these rules:

- Side effects remain behind the Action Gateway, required verifiers, and adapter or driver execution boundary.
- Required verifier, policy, work-order, trace, state, approval, capability, data-use, and safety uncertainty fails closed.
- State changes remain explicit, versioned, trace-linked, and replayable.
- Replay defaults to inspect-only or safe simulation and never executes live side effects by default.
- Tenant, agent, run, workload, lease, node, instance, action, state, trace, message, work-order, approval, artifact, dataset, model, change, deployment, and incident IDs stay distinct.
- Messages, feedback, reward, evidence, observability, and extensions are not authority.
- Training, evaluation, improvement, change, and deployment stay separated; training can publish candidates only.
- Physical orchestration remains high-level and locally safety-vetoable; Splendor does not replace motors, firmware, flight controllers, PLCs, ROS/native drivers, or hard real-time control.
- Planning PRs, RFC drafts, imported task rows, and documentation-only work are not implementation evidence.

## Assignment Rules

Use this checklist when turning a sprint slice into an issue or sub-agent task:

- Name the catalog task IDs, issue links, milestone/sprint fit, primitives, and boundary.
- Include explicit non-goals copied or narrowed from this plan.
- State whether the output is RFC/docs-only, schema/API work, runtime implementation, tests, examples, or validation.
- Require denial, failure, trace, state, replay, compatibility, and fail-closed evidence for implementation work.
- Require generated type or schema validation for public contract changes.
- Require docs/examples for behavior changes and known-limitation updates for deferred behavior.
- State that gold cases move from `not_exercised` only after exact executable fixtures or harnesses pass.
- Keep #147-#151 as completed planning/reference PRs and do not treat them as runtime evidence.
