# Component Responsibility Matrix

This is the shortest authoritative answer to “which component owns this?” The detailed contracts are in the numbered documents. A component may call another component, but it must not absorb the other component's authority or lifecycle. The imported source pack also includes the machine-readable view [`architecture/components.yaml`](architecture/components.yaml). In this repository, that file is active catalog source material, not proof that a current generator or CI drift check exists.

| Component | Owns exactly | Receives | Emits | Must never do |
|---|---|---|---|---|
| **Identity Registry** | Stable identities for tenants, humans, services, agents, nodes, devices, and governance authorities | Registration/rotation requests and proof material | `Principal`, identity status, revocation facts | Grant operational capability merely because an identity exists |
| **Authority Service** | Capability issuance, narrowing, expiry, delegation, revocation, and authorization decisions | Principal, requested operation, scope, policy refs, evidence | `CapabilityGrant`, allow/deny reason, authority audit event | Infer authority from prompts, metadata, messages, or ownership alone |
| **Secret Broker** | Short-lived secret leases and delivery to an isolated execution boundary | Authorized secret reference and workload/driver identity | `SecretLease`, lease audit events | Put secret bytes in state, traces, artifacts, prompts, action parameters, or datasets |
| **Artifact Registry** | Immutable identity, integrity, metadata, storage reference, retention class, and lifecycle of artifacts | Artifact bytes/reference and manifest | `ArtifactRef`, `ArtifactManifest`, verification status | Decide whether an artifact is good enough for deployment |
| **Lineage Service** | Derivation graph among data, code, environment, model, checkpoint, eval, world, and deployment artifacts | Parent refs, transform identity, parameters, run/evidence refs | `LineageEdge`, closure queries, reproducibility graph | Treat a mutable URI or tag as immutable identity |
| **Data-Use Controller** | Legal/policy purpose, allowed operations, locality, retention, and audience for data | Data subject/classification, requested use, principal/workload | `DataUseGrant`, denial, expiry/revocation event | Allow training access because inference access exists, or vice versa |
| **Event Log** | Append-only ordered facts with identity, causality, schema, integrity, and payload references | `EventEnvelope` append requests | Durable event IDs, subscriptions, causal queries | Be used as mutable state or silently drop required privileged events |
| **State Service** | Versioned mutable heads over immutable commits, partition ownership, compare-and-swap, snapshot and merge policy | State transition proposal, expected head, evidence refs | `StateCommit`, new `StateHead`, conflict result | Accept unversioned mutation or let replay alter a live head by default |
| **Evidence Service** | Bundles the exact facts needed to explain, reproduce, approve, or reject an operation/change | Event, artifact, eval, approval, incident, and environment refs | `EvidenceBundle`, completeness result | Claim certainty that its referenced evidence does not support |
| **Replay/Simulation Service** | Reconstruct, re-evaluate, or simulate recorded execution under explicit non-live drivers | Evidence range, state/artifact versions, simulation policy | Replay report, divergence report, counterfactual artifacts | Execute live side effects or become the architecture's central abstraction |
| **Node Agent** | Local resource inventory, execution leases, isolation enforcement, health, checkpoint transfer, and local device safety hooks | Signed placement/lease and workload package | Resource offers, workload events, metrics, result/checkpoint refs | Broaden a work order, leak one tenant's data, or cede physical emergency veto |
| **Fleet Scheduler** | Admission, placement, preemption, gang/rendezvous formation, fairness, locality, and interference control | `WorkloadSpec`, `ResourceOffer`, policy/SLO state | `PlacementDecision`, `ExecutionLease`, preemption/queue events | Execute user code, edit training logic, or consume protected holdouts itself |
| **Workload Controller** | Lifecycle of one logical computation across retries, workers, checkpoints, and outputs | `WorkloadSpec`, leases, worker events | Workload status, output artifact refs, failure decision | Activate a candidate merely because the workload succeeded |
| **Driver Registry** | Driver manifests, compatibility, maturity, certification, and operation lookup | `DriverManifest`, conformance evidence | Resolved driver/version, compatibility result | Let a driver self-certify or silently change operation semantics |
| **Driver Gateway** | Typed invocation lifecycle, authority/gate enforcement, idempotency, cancellation, timeout, postconditions, compensation linkage | `Invocation`, capability, gate policy, resolved driver | `InvocationResult`, usage, postcondition and evidence events | Route around a verifier, execute unknown-schema operations, or promise rollback for irreversible effects |
| **Perceptor Driver** | Acquire and normalize observations from a declared source | Collection request, source/data grant, schema | `PerceptEvent`, quality/freshness/provenance metadata | Grant action authority or write arbitrary world truth directly |
| **Actuator Driver** | Translate approved high-level actions to tools/services/devices and report outcomes | Approved invocation and bounded credentials/lease | Outcome, resource usage, postconditions, compensation ref | Decide its own permission or bypass local physical safety |
| **Model Driver** | Execute inference/scoring/embedding/generation against an immutable model bundle | Model ref, typed request, inference workload lease | Typed model result, usage, model/version evidence | Mutate live weights or select deployment versions outside routing policy |
| **Trainer Driver** | Run a declared learning algorithm and produce checkpoints/candidates | Training plan, code/env/data refs, worker context | Checkpoint refs, metrics, `CandidateBundle` | Read protected eval data, activate candidates, or rewrite lineage |
| **Evaluator Driver** | Apply a versioned eval protocol and produce signed/traceable measurements | Candidate/baseline refs, eval suite, protected data grant | `EvalReport`, slice results, uncertainty, evidence | Train on its protected inputs or translate “inconclusive” into “pass” |
| **Data Operator Driver** | Collect, parse, redact, normalize, label, deduplicate, split, quality-check, or quarantine data | Collection/data-workload spec and grants | Data shards, dataset snapshot/report artifacts | Mutate an immutable snapshot or remove provenance to improve a metric |
| **Sandbox/Executor Driver** | Run shell, Python, OCI, VM, Kubernetes, or custom jobs in a declared isolation profile | Workload package, env/artifact refs, scoped mounts/network/secrets | Exit/result artifacts, resource usage, execution evidence | Be an unrestricted host shell or make its environment implicit |
| **Agent Registry** | Versioned `AgentSpec` and component/deployment references | Agent definitions and validated updates | Agent revision, compatibility result | Contain private chain-of-thought or implement the agent's intelligence |
| **Agent Instance Controller** | 24/7 lifecycle, inbox, route execution budget, state-head binding, health, pause/resume/drain | Agent revision, percept/message triggers, leases | Route steps, proposals, state commits, instance status | Treat internal model output as an authorized external action |
| **Route Runtime** | Typed crossings among neural, symbolic, state, human, sub-agent, and driver steps | User-space route code/spec and current context | `RouteStepEvent`, typed results/proposals | Require one graph framework or inspect/standardize hidden reasoning text |
| **World-State Service** | Governed shared beliefs/facts/hypotheses with provenance, confidence, time, ownership, and conflict policy | Percept-derived or computed state proposals | World-state commits, conflict/uncertainty events | Equate a neural latent with verified external truth |
| **Message/Delegation Service** | Typed delivery and explicit narrower authority transfer to agents/sub-agents | Message/delegation proposal and parent scope | Message lifecycle, `DelegationGrant`, causal link | Make a message itself a permission token or implicitly inherit parent power |
| **Collection Controller** | Convert permitted sources/events into bounded collection and curation workloads | `CollectionPlan`, data-use rules, triggers | Snapshot/report refs, collection status | Continuously collect unspecified data “for future use” |
| **Feedback Service** | Attach human, environment, automated, or downstream feedback to an exact target/version | `FeedbackRecord` with source/provenance/use policy | Durable feedback event, conflict/trust views | Collapse heterogeneous feedback into one unqualified scalar |
| **Reward Derivation Service** | Produce versioned teaching/reward signals from exact feedback/outcomes | Feedback/event refs and derivation artifact | `RewardSignal`, `RewardDerivation` lineage | Hide normative choices inside an unlabeled reward number |
| **Eval Controller** | Eval-run lifecycle, protected access, baseline/candidate comparison, aggregation, and report publication | `EvalSuite`, candidate/baseline, leases | `EvalRun`, `EvalReport`, gate-ready evidence | Let candidate code select or alter its judge without an explicit change |
| **Training Controller** | Training-plan validation, data/code/env binding, workload creation, checkpoint/candidate collection | `TrainingPlan` | Workload refs, training run, `CandidateBundle` | Merge training and deployment into one operation |
| **Improvement Controller** | Diagnose triggers and propose bounded data/eval/train/search/change work | Monitoring/feedback/incident/eval evidence | `ImprovementProposal`, authorized child workloads | Grant itself new authority or suppress unfavorable evidence |
| **Change Controller** | Immutable diff, risk classification, required evidence, dependency ordering | Candidate artifacts and proposed target revision | `ChangeSet`, validation status | Edit values, code, model, route, data, or driver in place |
| **Gate Engine** | Deterministic/declared promotion conditions, obligations, approvals, exceptions, and fail-closed decisions | Change/proposal, policy, evidence, runtime facts | `GateDecision` | Generate the candidate it is judging or let missing evidence count as success |
| **Deployment Controller** | Shadow, canary, progressive rollout, activation pointers, stop conditions, quarantine, and rollback | Approved `ChangeSet` and `DeploymentPlan` | Deployment revision/status, cohort assignment, rollback events | Overwrite last-known-good artifacts or call irreversible effects “rolled back” |
| **Incident Controller** | Detect, classify, contain, investigate, and close safety/quality/availability incidents | Monitor/eval/gate/driver/fleet events | `Incident`, containment actions, evidence and lessons | Silently train on incident data outside its declared use policy |
| **Observability Exporter** | Export selected metrics/traces/evidence without changing kernel truth | Subscriptions and redaction/export policy | External telemetry | Become the source of authority or expose secrets/protected payloads |

## Cross-cutting rule

A component may **propose** work outside its responsibility, but the owning component remains the only authority that validates and commits it. For example, an agent can propose a data collection job, but the data-use controller and collection controller decide whether and how it runs; a trainer can propose a candidate, but the change, gate, and deployment controllers decide whether it becomes active.
